# 練習室 503 清零 ＋ 誠實終止實作計畫

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** hint 與 debrief 不再因為我們自己的守門而讓使用者拿到「生成失敗，可以再按一次」；她封鎖使用者時，系統要能誠實表達並自動給出拆解。

**Architecture:** 三條工作線。W1 讓「本輪沒有可貼句」成為合法輸出而非失敗；W2 以**她自己的逐客令宣告**（不是使用者輸入分類）觸發終止狀態；W3 把守門依「安全紅線／結構格式／主觀品質」三類重新定位，只有第一類可以擋死。

**Tech Stack:** Deno + TypeScript（Edge），Flutter client。預期無 migration。

## 先講清楚「零 503」的邊界

不是所有 503 都能消滅，硬要保證會變成說謊：

| 類型 | 能不能消滅 | 做法 |
|---|---|---|
| **我們的守門打回了本來可用的內容** | **能，且必須** | W1＋W3。這是真正的 bug 類型，也是 08-05 事故的成因 |
| 她真的封鎖了、沒有可貼句 | 能 | W1＋W2：那不是失敗，是合法結果 |
| 模型逾時／5xx／死線耗盡（**根本沒有輸出**） | **不能** | 沒有任何內容存在，任何「保底卡」都是我們自己編的假教練建議。只能改成誠實訊息，不要出現「再按一次」這種無效引導 |
| 安全紅線（L4／洩漏／捏造）兩發全踩 | 不該消滅 | 端出去比擋掉更糟。改成誠實說明，不重試 |

**驗收標準**：`ai_logs` 裡 `status=failed` 且 `failureCodes` 全屬「結構格式」或「主觀品質」兩類的筆數 → **0**。安全類與傳輸類不列入。

## W1：「本輪沒有可貼句」成為合法狀態

不同的可貼回覆，於是判 `hint_quality_invalid_duplicate_replies` → 503。

### Task 1.1：hint schema 允許 noPasteableReason

**Files:** `supabase/functions/practice-chat/hint.ts`、`hint_test.ts`

- `HINT_TOOL_SCHEMA` 新增可選欄位 `noPasteableReason: string | null`
- `PracticeHintResult` 新增 `noPasteableReason?: string`
- 當 `noPasteableReason` 非空時：`replies` 允許為空陣列，且**跳過**所有 pasteable 相關守門
  （duplicate/pure_questions/substantive_move/invite_route/grounding），但**甲類守門照跑**
  （L4／洩漏／罐頭／fact ledger 仍要驗 coaching 與 reason 文字）
- 測試：她已封鎖的 fixture → 解得出 result，`replies.length === 0`，`noPasteableReason` 有內容
- 測試：`noPasteableReason` 為空時，兩句可貼回覆仍是必填（既有契約不鬆動）

### Task 1.2：prompt 教她什麼時候該用

在 hint prompt 明確寫：對方已被封鎖／她已明確要求停止聯絡時，不要硬擠可貼句，

### Task 1.3：client 呈現

### 實作偏離（都有生產數據或風險理由）

1. **丙類擴白名單：不做。** 計畫原本要把主觀品質類整批納入 salvage。實測近 7 天
   只有 `invite_route`／`pure_questions` 各觸發 1 次，且都與 `not_grounded` 同一筆
   ＝早就被救回。擴名單買不到任何東西，卻要整批放寬品質底線——那正是 Codex 二審
   P1（臆測對方心理狀態無守門）沒解決的地方。已在
   `practice_visible_quality_test.ts` 用測試釘住「刻意不入列」。
2. **debrief 超長不 clamp。** `debrief_quality_invalid_overlong` 近 30 天 0 次，
   而 `generatedVisibleString` 有 ~15 個呼叫點，為零觀測收益改動全部呼叫點不划算。
   hint 側的 overlong 只需三行就改完，已做。
3. **`debrief_missing_fields` 不納入降級。** 計畫把它列為乙類，但 strengths/
   watchouts 全空的卡是「使用者看得到的殘卡」而不是形狀壞掉，端出去比 503 更糟。
   已用測試釘住 degrade 路徑照樣擋。

### 實作時新發現並一併修掉的

- **W1 的 client live 路徑漏做（真 bug，會讓 W1 完全不生效）**：W1 只改了
  `practice_hint.dart` 的 `fromJson`（快照還原用），但 `requestHint` 走的是
  `practice_chat_api_service.dart` 的 `_parseHintResult`——它硬要求 `replies.length == 2`
  且完全沒讀 `noPasteableReason`，會把 server 端出的合法形狀判成 `malformed_hint`。
  client 宣告了能力卻畫不出來。已修並補三顆測試。
- **旁白句從來沒有守門**：整句被括號包住的文字被當成可貼句端給使用者，貼出去
  會連括號一起送。新增 `isStageDirectionText`；兩欄都是旁白＝等同「本輪沒有可貼句」，
  單欄旁白前兩發照擋、salvage 端出另一句。
- **模型會把 null 寫成字串 `"null"`**（ai_logs 實例），`parseGameBreakdown` 會因此
  丟掉整張卡。已與真 null 同等處理。
- **retry advice 取全部發數而不是最後一發**：只看最後一發會出現「第一發 provider
  timeout、第二發被守門擋掉 → 告訴使用者重試無效」，但其實連線就是不穩。改成
  只有**每一發**都是內容類才敢說重按沒用。

## 2026-08-06 拍板：salvage 從白名單翻成黑名單

**Eric 的話**：「明明我們這個 AI 練習室就只是練習模擬真人聊天。我要求很明確，
不准有 503 發生。」

**為什麼原本的做法到不了那裡**：W3 用的是**白名單**——列出「哪些敗因可以放行」。
守門碼有五十幾個，名單只列了 9 個，沒列到的照樣殺。這種形狀注定要一條一條吵：
每審一輪就冒出新的邊界要討論，而使用者拿到的還是 503。

**新規則（唯一一句）**：兩發全滅時，**只有紅線可以殺，其他一律端出去**。

紅線只有三類（`practice_visible_quality.ts` 的
`NEVER_SALVAGEABLE_FAILURE_CODE_PARTS`）：
1. `_l4_unsafe`——露骨性內容
2. `_internal_label_leak` / `_temperature_leak`——洩漏內部機制
3. `_canned_visible_text`——我們自己寫死的罐頭句混進模型輸出

**捏造事實刻意不在紅線內。** 我當面提過代價——兩發都編造時，AI 可能跟使用者說
她沒說過的事（例如「那間咖啡店叫黑露」），使用者照著聊會被拆穿——Eric 拍板
「不留」，選擇字面上的零 503。**要改回來＝重新對齊 Eric，別自己改回去。**
這個代價已經寫成 `index_test.ts` 的斷言（`includes("黑露") === true`），
將來有人想動會先看到。

**實作**：新增總開關 `salvagePass`（hint 與 debrief 各一），開了就等於宣告
「不端出去使用者就拿到 503」，此時紅線以外的 gate 全部讓路。**前兩發完全不受
影響**——該擋照擋，retry 仍有機會產出乾淨內容，所以只有「兩發都爛」才會降級。

**順帶解掉的**：`hint_no_pasteable_unsupported_state` 不再是 503 來源。認不出
逐客令時改成端出**不提她**的中性說明（`SERVER_NO_PASTEABLE_REASON_NEUTRAL`），
