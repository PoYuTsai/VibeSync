## 0. 一頁結論

- 「高階互動指南」是 `ebook_shelf_section.dart` 的標題卡，底下掛《交友軟體實戰 · 終極指引》四冊與《成為獎賞：魅力進階課》三冊。內容真源是 `assets/learning/ebooks/book_1..7.json`（322 KB、約 4 萬字、558 個區塊、130 條條目、17 顆前往按鈕）。
- 兩個單元的病因不同：
  - **終極指引四冊**是夥伴原文用 `tools/content` 機械轉入、一字未改。「不容易閱讀」大多是轉換留下的機械性問題：半形標點 1,169 處、表格攤成「A｜B」管線 70 處、小節標題遺失（診斷樹第二～五層、十二週計畫的週次）、原課本的內部指涉（課本 6.1／第六節／階段 2.6／類型 A）、多行文字塞進單一區塊且行首帶空白、過渡段掉在錯的位置。「不夠口語化」集中在說明段的統計／經濟／工程用語（基準率、目標函數、期望值、邊際效益、資訊經濟學、合理化引擎、回傳、預測因子）與第 3 冊警告區。

## 3. 兩個單元的病因（給拍板用的白話版）

- **終極指引像一份被硬塞進手機的講義。** 夥伴的原檔是桌機版單檔 HTML：有表格、有「見案例 K」「課本 6.1」這種翻頁式指涉、有 h3／h4 小標。轉換器只做結構映射、不改字，所以表格變成「A｜B」字串、小標掉了、指涉還指著課本頁碼、`<br>` 縮排變成行首空白。這些不是夥伴寫得不好，是載體換了。修這些不需要改他一個字。
- **終極指引的語氣是給「會讀論文的人」寫的。** 「基準率」「期望值是負的」「選擇效應是反的」「這是資訊經濟學問題，不是面子問題」「目標函數是把人約出來」——論證是對的，但 TestFlight 的目標讀者是滑交友軟體卡關的一般男生。同一件事可以講成「失敗本來就是常態」「整體算下來是賠的」。這一層才是真的「改夥伴的字」，要他同意。
- **成為獎賞寫得口語，但一口氣講太長。** 第 6 冊有 40 個欄位裡面塞了兩三段，第 5 冊 1.7 一個欄位 171 字還內嵌兩組 ✕／✓ 對照。手機上一整塊灰字沒有停頓點，讀者不知道哪裡可以喘；對照沒有顏色與圖示，眼睛掃不到重點。這一層不改字，只拆區塊。

## 4. 逐冊片段清單（Before → After）

每條格式：`區塊 id`（問題型別）：問題 → 改法。改寫文字是可直接貼進 JSON 的建議稿；標「需夥伴確認」的是要補資訊或改他原意的地方。

### 4.1 第 1 冊《診斷 · 配對開場》（免費，3,189 字，193 個半形標點）

**1.1 你卡在哪一段**

- `ebook-1-c1-b1`（T9）：「結果也遠勝於此」書面；「0.5 個約會」抽象。→ 兩週只配對到 3 個人的話，就算你聊天技巧滿分，天花板也只有 3。把對話轉化率翻一倍，你只是從半個約會變成一個；但把配對數從 3 拉到 30，就算聊得普普通通，結果也差很多。所以先修最前面的瓶頸。
- `ebook-1-c1-b2`（T9）：「失敗的基準率很高，這是結構」統計用語。→ 第二個觀念：失敗本來就是常態，這是遊戲規則，不是你有問題。大部分配對不會變成對話，大部分對話不會變成約會。要是你把每次失敗都讀成「我做錯了什麼」，你就會開始修理沒壞的東西，還會在對方沒興趣的時候繼續加壓——那才是真正把結果搞砸的行為。
- `ebook-1-c1-b3`（T6）：與漏斗 intro 逐字重複，而且排在漏斗之後卻寫「看下面五句話」。→ 刪除。
- `ebook-1-c1-info4`（T7）：轉換器塞的固定句「想更嚴謹的話，往下這一段是給你的。」只是標題殼。→ 改 `heading`「想更嚴謹？記錄這六個數字兩週」，刪 callout。
- `ebook-1-c1-b5`＋`ebook-1-c1-tbl6`（T3、重複）：b5 內嵌「A 配對數 / B …」六項，tbl6 又列一次且帶表頭「記錄項｜說明」與管線。→ b5：先不要改任何做法，只記錄下面六個數字。沒有數字就沒有診斷。大多數人靠感覺判斷，而感覺通常指向錯的地方——讓你最挫折的那段對話，不等於問題就出在對話。tbl6：刪 title，items 改「A. 配對數：兩週內配對到幾個」「B. 有回覆的：你發第一則訊息後有回你的」「C. 撐過五輪的：一來一往五次以上還活著的」「D. 你開口約的：實際提出見面的」「E. 答應的：說好的」「F. 真的到場的：實際見到面的」。
- `ebook-1-c1-b7`（T9）：四條原則沒有標題；items[3]「無法回傳這個答案的系統」是程式用語。→ 加 title「先記住四條」；items[3]：診斷的第一個選項永遠是「她沒興趣」。一套不允許這個答案出現的方法，只會讓你在錯的地方越挖越深。

**1.2 照片：六個功能位**（測試要求保留「六個功能位」，章名已含）

- `ebook-1-c2-b1`（T9）：「軟體介面決定決策」「它不聰明、需出門拍照」電報體。→ 交友軟體的介面已經決定了大家怎麼做決定：一到兩秒，看照片，滑掉或留下。照片決定絕大部分的配對結果，文字要等照片過關才會有人讀。這一關最少人認真練——因為它一點都不聰明，還得出門拍照，窩在家研究話術舒服多了。但它的槓桿是整條漏斗裡最大的。
- `ebook-1-c2-tbl2`（T3）：caption「位置｜功能｜常見錯誤」；每條展開後的內文其實是「常見錯誤」欄但沒有標籤；第 6 條內文只有「—」。→ caption「六張照片各有一個工作。點開看這一張最常犯的錯。」；每條內文前綴「常見錯誤：」；第 6 條「—」→「常見錯誤：沒有固定規則——放一張你最想被問的。」（需夥伴確認）。
- `ebook-1-c2-b3`（可選）：六條自檢其實是 checklist，可改 `checklist` 讓讀者勾。

**1.3 Bio 與外顯呈現**

- `ebook-1-c3-b1`（T9）：分號串接；「傳遞防衛而非選擇性」抽象。→ Bio 太長沒人看。條列自己的優點沒有說服力；條列對對方的要求（「不要 xxx 的勿擾」）更是扣分，因為她看到的是防備，不是你有在挑。有效的結構：一句具體的生活細節＋一句幽默或自嘲＋一個開放的鉤子。
- `ebook-1-c3-cmp2.caption`（T9）：「強在:…」→「強版本強在三件事：具體（不是「喜歡美食」而是「煎蛋不黏鍋」）、自嘲（拉近距離）、最後一句給她一個幾乎零成本的開口。」建議搬進 strong item 的 `note`（renderer 已支援，說明就貼在它解釋的那句下面）。
- `ebook-1-c3-b3`（T9）：「最大的單一變數」「那個時點不存在」。→ 照片能修的有限，因為照片拍的終究是你。長期來看影響最大的是體脂和體態，再來是髮型、皮膚、衣服合不合身。這要花六到十二個月，所以現在就開始，後面的階段同時進行。不要等「準備好了」才開始用軟體——那一天不會來。
- `ebook-1-c3-grad4`（T7）：`.grad` 映成 principle，kicker 顯示「原理」但內容是畢業標準；「→ 進入階段 1」電報體。→ tone `goal`、title「畢業標準」、text「配對數明顯上升，而且你不再覺得配對是碰運氣。做到了，就進入階段 1。」同型五處：`1-c4-grad13`、`2-c4-grad16`、`4-c3-grad9`、`4-c5-grad8`。

**1.4 開場：聊她／聊我／聊我們**

```python
"""把電子書 JSON 裡 CJK 語境的半形標點轉成全形，並清掉多行文字的行首空白。

規則（只碰含有 CJK 的字串欄位；id／enum／sourceRefs 一律不碰）：
  ,  → ，   （數字之間例外：1,000）
  :  → ：   （數字之間例外：10:00、2:1）
  ;  → ；      ?  → ？      !  → ！      ( ) → （ ）
  ... → ……     / → ／（並去掉兩側空白）     ' + ' → ＋
  ' = ' → ＝、' > ' → ＞（英數之間例外：V=0）
  全形標點旁的半形空白移除；每行去頭尾空白；三個以上換行壓成兩個。
用法：python3 normalize_ebook_punct.py --check  files...        只報數字、不寫檔
      python3 normalize_ebook_punct.py --out DIR files...       寫到 DIR
      python3 normalize_ebook_punct.py --in-place files...      直接覆寫
"""
import json, re, sys, os, collections

SKIP_KEYS = {'id', 'type', 'tone', 'stance', 'speaker', 'signal', 'mode', 'retryPolicy',
             'targetBookId', 'targetChapterId', 'targetEntryId', 'unit', 'access', 'theme',
             'document', 'sections'}
CJK = re.compile(r'[\u3400-\u9fff\uf900-\ufaff]')
FW_AFTER = '，。：；！？）」』》】／＋＝＞、'   # 這些前面不留半形空白
FW_BEFORE = '，。：；！？（「『《【／＋＝＞、'  # 這些後面不留半形空白


def normalize(text, stats):
    if not CJK.search(text):
        return text
    out = []
    n = len(text)
    for i, ch in enumerate(text):
        p = text[i - 1] if i > 0 else ''
        nx = text[i + 1] if i + 1 < n else ''
        rep = None
        if ch == ',' and not (p.isdigit() and nx.isdigit()):
            rep = '，'
        elif ch == ':' and not (p.isdigit() and nx.isdigit()):
            rep = '：'
        elif ch == ';':
            rep = '；'
        elif ch == '?':
            rep = '？'
        elif ch == '!':
            rep = '！'
        elif ch == '(':
            rep = '（'
        elif ch == ')':
            rep = '）'
        if rep:
            stats[ch] += 1
            out.append(rep)
        else:
            out.append(ch)
    s = ''.join(out)
    before = s
    s = s.replace('...', '……')
    stats['...'] += before.count('...')
    stats['/'] += s.count('/')
    s = re.sub(r'\s*/\s*', '／', s)
    stats['+'] += s.count('+')
    s = re.sub(r'\s*\+\s*', '＋', s)
    eq = re.compile(r'(?<![A-Za-z0-9])\s*=\s*(?![A-Za-z0-9])')
    stats['='] += len(eq.findall(s))
    s = eq.sub('＝', s)
    gt = re.compile(r'(?<![A-Za-z0-9])\s*>\s*(?![A-Za-z0-9])')
    stats['>'] += len(gt.findall(s))
    s = gt.sub('＞', s)
    s = re.sub(r' +(?=[' + re.escape(FW_AFTER) + '])', '', s)
    s = re.sub(r'(?<=[' + re.escape(FW_BEFORE) + ']) +', '', s)
    s = '\n'.join(line.strip() for line in s.split('\n'))
    s = re.sub(r'\n{3,}', '\n\n', s)
    return s


def walk(obj, stats, touched):
    if isinstance(obj, dict):
        for k, v in obj.items():
            if k in SKIP_KEYS:
                continue
            if isinstance(v, str):
                nv = normalize(v, stats)
                if nv != v:
                    touched[0] += 1
                    obj[k] = nv
            else:
                walk(v, stats, touched)
    elif isinstance(obj, list):
        for i, v in enumerate(obj):
            if isinstance(v, str):
                nv = normalize(v, stats)
                if nv != v:
                    touched[0] += 1
                    obj[i] = nv
            else:
                walk(v, stats, touched)


def main(argv):
    mode = '--check'
    out_dir = None
    files = []
    i = 0
    while i < len(argv):
        a = argv[i]
        if a in ('--check', '--in-place'):
            mode = a
        elif a == '--out':
            mode = '--out'; out_dir = argv[i + 1]; i += 1
        else:
            files.append(a)
        i += 1
    for path in files:
        raw = open(path, encoding='utf-8').read()
        data = json.loads(raw)
        stats = collections.Counter(); touched = [0]
        walk(data, stats, touched)
        print(f'{os.path.basename(path)}: fields changed={touched[0]} ' +
              ' '.join(f'{k}={v}' for k, v in sorted(stats.items()) if v))
        if mode == '--check':
            continue
        dump = json.dumps(data, ensure_ascii=False, indent=2) + '\n'
        target = path if mode == '--in-place' else os.path.join(out_dir, os.path.basename(path))
        os.makedirs(os.path.dirname(target) or '.', exist_ok=True)
        open(target, 'w', encoding='utf-8').write(dump)


if __name__ == '__main__':
    main(sys.argv[1:])
```

## 附錄 C：半形標點的鄰接分佈（決定規則用）

以 1,169 個半形標點的前後字元分類（腳本 `punct_edges.py` 的輸出摘要）：

- `,` 516：471 個前後都是中文；45 個接在其他標點或英數旁；只有 1 個前面是數字（「30,即使」）而且後面是中文——沒有「1,000」型的千分位。
- `(` `)` 各 191：沒有任何一個是「英數(英數)」的程式碼型用法。左括號 106 個前後都是中文、26 個在行首、26 個接在 ↑ 或 emoji 後面；右括號 61 個在句尾、78 個接其他標點。
- `:` 181：130 個前後都是中文、17 個在句尾、7 個是「數字:數字」（10:00、15:00、21:00、2:1）——只有這 7 個保留半形。
- `?` 68：全部前面是中文，33 個在句尾，沒有一個接在英文後面。
- `;` 21：全部在中文之間。
- 另有 `...` 4、` / ` 38、` + ` 32、` = ` 4（V=0 型 6 個保留）、` > ` 5。

規則設計的依據：括號沒有程式碼型用法所以全轉；冒號只在數字:數字保留；問號、分號、逗號無例外。
