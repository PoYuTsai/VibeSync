### 最關鍵的一條鏈（失格→賦格→降階邀約）

```
她：「普通欸」「沒有很好」（酒量）
他：「那好像不能找你喝酒」「你會不會吐在我身上哈哈」   ← 失格
她：「我沒那麼遜ㄟ」「你不要灌我」「我就不會吐」        ← 她開始自我證明＝成功

她：連發 5 則解釋咖啡因敏感                          ← 投入度爆表
```

## 二、Eric 這輪的拍板（照時間序）

1. **字回太多** → 目標 20-40 → 12-28 → **8-20 字**，每則 2-15 字多數 4-10。
2. **「笑死」可以寫，不用怕** → 放行 2-5 字純情緒短則，至少一則 ≤6 字。
3. **女生要多顆球回**（模擬真實）→ NPC prompt 改成 1-3 則、則數由心情決定。
4. **hint 也可以分則** → 換行分則，UI 拆泡。
5. **中英夾雜比較接近真實** → 先全禁（錯）→ 只准專有名詞（還是錯）→ **全面放行**。
   Eric 的範例：「那間 bar 蠻 chill」「都一直躲酒 我有點 sad」。
6. **台語＋注音諧音** → 放行（歹勢／母湯／甘安捏／ㄏㄏ／ㄟ）。
7. **打字太快會打錯** → NPC 允許小錯字、注音沒選到。
8. **hint 不猜使用者喜好，給選項最穩** → 兩顆球各走一個立場。
9. **廢測不能硬回**（他主動提醒）→ 偵測器排除質問句形。
10. **不要技巧中毒，平聊占大多數** → 戰術從「規定動作」降為「方向」。
11. **雙向篩選**：立場不同也是價值，但要用敘事不是說教。
12. **對話不是永無止盡**：Game 要在有限回合走完流程到速約。
13. **必須瘦身** → prompt 7514 → 7039（後續補規則回到 7140）。
14. **最後一顆球不要寫死** → 依 server 算出的速約階梯分四種講法。
15. **短不等於空** → 補平衡規則。

## 三、實作上的關鍵決定（含為什麼）

### 分則：一則訊息、一個 turn、一次請求（做法 B）
UI 依換行拆成多顆泡（上限 4），但**本地仍是一筆 `PracticeMessage`、上行仍是一則
user turn、扣一次額度**。不可以改成迴圈送 N 次——本地索引會和 `request.turns`
索引錯開，而 `appliedHintTurns[].turnIndex` 是 debrief「你有照提示做」責任歸屬的鍵。

### 逐字稿的則界要保留但不能被抄
`flattenMultiBubbleText()` 把換行換成**引號包每一則**（`「對呀」「算是緣份」`）。
原本用「｜」分隔，離線重放實測**模型會把分隔符當輸出格式抄走**，產出
「追劇喔｜那妳會邊吃東西嗎」這種單則裡塞直線的句子。引號是內容標記不是分隔符。

### server 算得出來的就不要讓模型猜
- `partnerBubbleRhythmPrompt`：她這則發了幾顆球 → 給節奏建議
  （她 1 則→回 2-3 則帶節奏；**她 4 則以上→只回 1 則短的把節奏收回來**）
- `stanceOptionPrompt`：她在問你的喜好 → 注入「兩顆球各走一個立場」硬指令
- `lastHintPrompt`：最後一顆球 → **依速約階梯**給四種不同講法

**教訓**：規則寫在契約裡第 N 條會被前面十幾條稀釋。立場選項原本只是一行規則，
離線重放三個情境全部沒觸發、而且模型自己編了「我會潛水」這種使用者沒說過的事。
改成 server 偵測後注入硬指令才生效。

### 立場選項的標籤
`HintReply.label` 型別從寫死的兩個字串放寬成 `string`；模型可填
`warmUpLabel`/`steadyLabel`（2-6 字），**清洗失敗一律退回預設、絕不 throw**
（標籤只是卡片標題，不值得為它開 503 路徑）。client 本來就是 `Text(reply.label)`，
零改動。

### 廢測排除（Eric 提醒後補的）
`PARTNER_SHIT_TEST_QUESTION` 擋掉「每個女生／對誰都／很會講／編故事／套路／油／
想幹嘛／認真的嗎／在說什麼」。**硬給兩個認真的立場＝教使用者認真解釋自己，
比不給選項還糟。** 偵測矩陣 20/20 釘在 `hint_test.ts`。

## 四、踩到的坑（重複踩會很痛）

1. **守門會殺掉品質最好的候選**，而且看不出來——要 dump 被擋候選才知道。
   實例：「站到腿抖還打字，妳這反應有點讓人在意，我本來只想回一句的」（教科書級
   男女前提）被丟掉，只因為 coaching 漏寫「速約任務：」五個字。
2. **戰術行同時給兩個選項時，模型 100% 挑好寫的那個做。** 「男女前提／生活樣本」
   並列時男女前提整場長不出來。一行只給一個動作。
3. **中文沒有詞邊界**，邀約分類器連環誤判：
   - 「跟我**一樣**」被讀成「跟我一起」
   - 「看**來我這**關過了」命中「來我這（裡）」
   - 「跟妳**打**個招呼」命中「打（球）」
   - 「我們一起看片**大概會**搶遙控器」＝想像畫面被當成邀約
   全部修成負向前瞻／後顧，並加了假想語氣豁免。
4. **`厂` 是 `廠` 的簡體字**：台灣人打「厂厂」當笑聲會被 `toTraditionalChinese`
   轉成「廠廠」。prompt 要求打真注音 `ㄏㄏ`，已加測試釘住。
5. **模型偶爾把換行寫成字面 `\n`**：加 `normalizeLiteralNewlines()` 修復。
6. **`GAME_INVITE_ROUTE_ADVICE` 是雙用的**——它也會顯示在 fallback 卡的心法裡，
   禁令例句寫進去會漏給使用者看到。prompt-only 的規則要放 `speedInviteLadderPrompt`。
7. **瘦身時別刪「骨架 P1→P5」**：那是 hint／NPC／debrief 三個介面的對齊不變量，
   有測試釘死。
8. **提高守門召回會讓首發更常被擋**（Eric 明確否決）。漏判的邀約句形改在
   **prompt 端讓模型不產出**，不動守門。
