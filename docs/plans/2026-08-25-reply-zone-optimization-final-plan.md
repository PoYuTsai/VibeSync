## 第一部分：Codex 第三輪審核的查證結果

Codex 這輪給「有條件通過」＋四個必改缺口。逐一到程式碼驗證：**四個必改全部成立**，本版全數採納（含兩處小修正與一處取捨）。

### 必改 1 成立：A0 不是「兩欄小改動」，是一條資料鏈的語意變更

查證：「複製＝照原句送出」這個寫法不只存在於一個函式——它牽動手機本地儲存（Hive）、雲端資料表（`20260706120000_coaching_outcome_events.sql`）、盡力上傳、結果追問列（Follow-up Bar）、成效摘要（digest）一整條鏈。改語意等於全鏈都要驗證相容。

（細節修正：上傳是直接寫 Supabase 資料表，沒有獨立的 Edge function——Codex 說的「Edge validator」不存在，但「全鏈驗證」的結論不變。）

**A0 定稿內容——完整狀態機**：
- `copyObservedAt`：系統客觀知道「複製發生了」的時間。複製只代表複製。
- `userAction`：只有使用者明確回答後才寫入（照原句送出／改過才送／沒有送／問了教練）。
- `userActionConfirmedAt`：使用者回答的時間。
- `outcome`：只有明確「有送出」之後才進入「等結果」狀態。
- 新舊口徑要分得開：舊資料的「sentAsIs＋pending」無法區分「只複製」和「真的送了」，**不得回填成明確直送**，直接排除在新版直送率之外。（用版本欄位還是「新欄位是否為空」來區分，留給實作 PR 決定，原則是分得開就好。）
- 驗證範圍：Hive、雲端資料表、上傳、Follow-up Bar、digest 全鏈。
- **修正一句話**：A0 的「不動畫面」改為「**不動回覆卡的資訊架構**，但 outcome 追問與狀態顯示會跟著新狀態機調整」。

### 必改 2 成立：曝光遙測移到 A1 做，A0 只定契約

查證：現有的 `AnalysisTelemetry` 是請求／辨識／耗時／額度的**診斷回報**，不是互動事件管線——「順手埋計數」在現有管線裡沒有落點。且 A1 會把版面改成「更多接法」，若在舊版面先埋曝光，事件語意馬上失效。

**定稿**：
- A0 只做兩件事：定義事件契約＋隱私規則。
- A1 隨新版面實作事件：`more_expanded`（展開更多接法）、`alternative_impression`（替代卡曝光）、`copy`、`refine`。
- 曝光要可機械驗證：卡片至少 50% 可見達 500ms 才算一次曝光，同一畫面工作階段去重。
- 事件至少帶：版面版本（layoutVersion）、頁面（surface）、穩定的卡片／建議 ID、位置、可見替代卡總數、client build。
- **絕不帶**：聊天原文、回覆文字、自訂微調指令。
- 落點：新的 append-only 事件通道，沿用 outcome 上傳鏈的隱私模式（細節在 A0 契約 PR 定案）。

### 必改 3 成立：A2a 不能拿 ball_coverage 當真值，要建人工金標集

查證兩點：① prompt 裡**已經有**「晚餐＋排超久併成同一球」的併球範例（stream_prompt）＋「蛋糕隕石坑」合併正例（examples），v1 說「再補一個併球範例」確實會重複；② `ball_inventory.ts` 的覆蓋驗證是「拿模型自己標的接／併／略，對照模型自己的輸出段」——**模型一開始切錯球，它照樣滿分**。循環論證屬實。

**A2a 定稿**：
- 先建**人工標註的分層金標集**（gold set）：每題由人標「正確的接／併／略」與「理想可傳訊息數」。情境涵蓋：單球、同一件事多句、真正多球、道歉／嚴肅、低投入、邀約排程、媒體／未接來電。起步規模 30–50 題（可從 voice-benchmark 既有案例擴充，用真實去識別對話）。
- 主指標：**假拆分率**（同一件事被拆開回）、**漏獨立球率**、自然度、像本人程度、願意直送。
- ball_coverage 降級為**回歸護欄**（防同一切球標準下的漏接），不當真值。
- Prompt 改動採 **one-in/one-out**：修改或壓縮既有範例，設 rendered prompt token 上限，不淨增範例。
- 驗收改成：**主指標必須提升；安全、漏球、延遲、token 採「不能變差」門檻**（不再要求六項全升）。

### 必改 4 成立：stretchLevel 凍結，不原地改義

查證：wire contract 明確定義 stretchLevel＝「離使用者舒適區多遠」，Edge 仍在正規化與權益過濾。原地改義成「本輪適配度」會讓新舊 client、舊快照的同一個欄位有兩種意思——相容性坑。

**定稿（技術預設，不需要 Eric 三選一）**：
- stretchLevel 凍結、標示 deprecated：契約保持相容、不展示、不拿來做任何決策。
- fitThisRound 另建**選填、含版本標記的影子欄位**。
- B2 契約升版時才移除 stretchLevel。
- fitThisRound 的準確性用**人工標註**校準（金標集裡一起標），不能拿模型自己的比例驗證自己。

## 第二部分：五階段定稿

### A0：把尺修準（量測校正）

> 目標一句話：讓數據說真話——複製就是複製，「有沒有送」只信使用者親口回報。

- 完整狀態機（見必改 1），全鏈相容驗證，舊資料標舊口徑、不回填。
- 定義 A1 要用的互動事件契約＋隱私規則（見必改 2）。
- **不做**：微調指令 lineage 記錄（原 v1 的「記最後採用的指令」有記錯版本的風險——使用者可在多輪版本間切回舊版，而結果只回傳文字沒有指令；既然偏好學習已延到上架後，這項整個移過去，A0 更乾淨）。
- 範圍修正：不動回覆卡資訊架構，但 outcome 追問與狀態顯示會調整。
- 屬**使用者資料高風險範圍**：進雙 AI review gate；上線順序「加法 migration → 相容 Edge/上傳 → client」。

### A1：介面減法（唯一動畫面的階段）

> 目標一句話：第一眼只看到「現在最適合傳的那組訊息」，其他要看再展開。

主體不變（首屏推薦組＋複製整組＋調整某一句；理由收合；其餘卡收進「更多接法」，**同次生成、預設收合**；「這版差別」取代罐頭文；紀錄頁推薦在前；白話標籤＋paywall 同步），加上這輪補齊的邊界：

- 「其餘四張」改為「**其餘 0–4 張**」：Free、舊快照、fallback 不一定有五版，卡組照實際存在的內容組。
- **單段推薦直接進微調；多段才先選句子**（現行設計本就只允許調單句）。
- **安全資訊永遠直接顯示、不進收合區**：shouldGiveUp（不建議回覆）、界線／安全警示、提醒，一律不收進「它接了哪些球」。
- 無推薦內容、或策略是「暫停」時，**不顯示「複製整組」**。
- 「這版差別」缺失時用固定標籤 fallback（server 端已有兜底文案，client 再兜一層）。
- 歷史紀錄**只改顯示層，不重寫既有快照**。
- 無障礙與驗收：VoiceOver 順序、Dynamic Type、收合狀態語意、Reduce Motion；前後視覺證據＋實機 iPhone dogfood。
- 快捷微調的點擊計數（太油／短一點⋯⋯按了哪顆）進 A1 事件契約——輕量、不記自訂文字，撐起「快捷點擊率」指標，不需要 lineage。

### A2a：Prompt 實驗（A1 dogfood 一輪後）

見必改 3 定稿：金標集為真值、ball_coverage 當護欄、one-in/one-out、主指標提升＋其餘非劣性。一次黑箱重驗。

### A2b：適配度實驗（與 A2a 分開、影子實驗）

- stretchLevel 凍結 deprecated（技術預設，見必改 4）。
- fitThisRound 影子欄位照跑：模型標、App 不顯示、只收數據。
- 準確性用金標集人工標註校準；使用者行為面用 A0 修正後、曝光校正過的採用數據。

### B2：架構演進（長期終態，條件觸發，暫不排開發）

終態欄位（這輪再補兩項，共六欄概念）：

- **actionKind**（頂層）：`sendReply | pause | askCoach`——只有 sendReply 才產生回覆版本；「暫停追」「適配確認」這類策略**不再硬塞成五句回覆**。
- **moveType**：這回合的動作。
- **tone**：語氣（自然、溫和、幽默、曖昧⋯⋯）。
- **fit**：本輪適配程度。
- **legacyStyleKey**：**可為空、帶版本的轉接欄位**——新組合對得上舊五風格才填，對不上就留空，不硬映射（硬映射會污染成效與付費統計）。
- 初期仍同次生成多版本，UI 只突出一個決策。

**啟動條件（修正版）**：
1. **替代卡的增量價值**：曝光到替代卡的族群，相對「只看推薦」的對照組，有沒有帶來更多複製／明確送出／更少微調。（「替代卡採用率低」本身不算證據——四張卡競爭一次操作本來就低。理想做法要 A/B 對照，需要輕量 feature flag——layoutVersion 欄位可承載；沒有 flag 之前，用「展開過 vs 沒展開」的觀察對照當參考值，但要知道它有選擇偏差。）
2. A2b 證明適配判斷可靠（人工校準）。
3. 離線盲測：新結構產出勝過現行五風格。

## 第四部分：暫緩與不做（不變）

**暫緩**：
- 偏好自動學習（含微調指令 lineage）：post-launch 另案。原則備忘：獨立 ReplyPreference、只學收斂方向、跨兩次分析＋三次採用才明示徵求同意、全域與單一對象分開、可查看修改刪除、只存代號不存原文、嚴肅情境不升格。若做 lineage：每個微調版本綁定標準化標籤與來源鏈，只記「被選中採用版本」的標籤，自訂文字永不上傳。
- Free 權益調整：post-launch 商業實驗（ADR #25 與 paywall 是付費結構）。

**明確不做**：五風格改 AI 自由命名、教練策略直接當回覆卡、temperature 調整、「點了才另外生成」的展開、stretchLevel 原地改義、舊 outcome 資料回填。
