## 1. 目標

用外部觀眾與真實 iPhone 證據判斷凍結 Animatic 是否真的工作；不邀請受測者改寫故事，也不以 AI 自評替代真人結果。

## 2. 樣本

- 8～12 位符合目標年齡的台灣使用者；基準採 10 人。
- 僅記匿名 Participant ID、年齡區間與裝置，不收姓名、聯絡方式或聊天內容。
- 同一位參與者依序完成 M1 黑箱與完整 Mobile Animatic；M1 回答提交前不得看到後文。

## 3. 固定流程

1. 播放 10 秒 M1-only Mobile clip 一次，不介紹 VibeSync、暗示或故事命題。
2. 立即記錄真人感 1～5、A／B／C、男主是否回錯與原話、哪一句像 AI／廣告。
3. M1 回答鎖定後，播放 92 秒完整 Mobile Animatic。
4. 奇數 Participant ID 開聲音；偶數 ID 靜音，避免全樣本只驗證單一音訊狀態。
5. 不提供四項產品事實選項，先讓參與者自由回想產品理解，再由記錄者依證據勾選。
6. 記錄必要文字可讀性、暈眩／失控與「是否只會生成回覆」的理解。

## 5. iPhone 實機 Gate

- Eric 在至少一台實體 iPhone、直式 100% 尺寸完整播放 Mobile MP4。
- 分別完成有聲與靜音觀看。
- 核對 M1、M3、M4、K1、K2、K3、兩則送出與 K7 CTA。
- 記錄機型、iOS、播放器、是否裁切／縮放、字幕可讀、掉幀與主觀暈眩。
- Reduced-motion Board 只驗證故事次序；它不是 production fallback 的效能證據。

## 6. 裁決

- 全部量化門檻與 iPhone Checklist 通過：本 Gate 才可標記通過，並重新計算 implementation plan。
- 任一門檻失敗：只重開對應層級，不以少數偏好重新共寫凍結台詞。
- 樣本不足、資料漏填或未完成實機：保持 `incomplete`，不得推論通過／失敗。

## 7. 治理

本 Gate 不授權 P0／P1、runtime、`marketing-site/`、build、commit、push 或 deploy。測試資料必須匿名；不保存參與者個資或真實私人聊天。
