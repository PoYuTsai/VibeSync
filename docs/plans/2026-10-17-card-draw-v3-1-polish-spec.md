一句話：**流程不動**（只翻一次、停住等點擊、收進那一格都保留），質感往參考片靠：整張卡會發光、SR 有自己的金色段與高潮、牌和星星有聲音、收卡是一道繞進那一格的金色弧線。

### 2.2 聲音（125 ms 窗 RMS）

兩邊用同一支程式量，轉單聲道後算。「手機近似」是先做 4 階 300 Hz 高通再算，近似 iPhone 喇叭放得出來的部分。我們這邊照 app 的音量與觸發時點合成（§14），揭曉起點 R0 從按下後 0.5 s 算。

| | 參考片（全頻） | 參考片（手機近似） | 我們 main，SR（全頻） | 我們（手機近似） |
|---|---|---|---|---|
| 等待 | 全靜音 | — | 只有按下時的咻聲（照 `docs/bug-log.md` 2026-07-16，維持） | — |
| 蓄力平台 | −31.7 dB | −32.9 dB | −29.4 dB | −30.7 dB |
| 翻牌高潮 | −13.5 dB（**+18.2**） | −27.4 dB（+5.4） | −17.6 dB（+11.8） | −20.8 dB（**+9.8**） |
| 稀有度牌 | −19.1 dB（比前一段 +9.2） | −20.0 dB（**+9.8**） | 沒有 | 沒有 |
| 星星 | −16.0 dB（+9.5） | −16.1 dB（**+16.0**） | 沒有（配樂剛好有個小起伏） | 沒有 |
| 落位 | −22.8 dB | −24.5 dB | −23.2 dB（收卡音） | — |

兩個結論：

1. 參考片的翻牌高潮 95% 的能量在 200 Hz 以下（低頻轟），用耳機聽差很多，但**手機喇叭上我們反而比它響**（+9.8 對 +5.4）。高潮要補的是耳機上的低頻份量，手機上靠諧波撐住（做法同 bed v4）。
2. 手機上差最多的是**牌和星星的重音**：參考片分別高出 9.8 dB 和 16.0 dB，我們完全沒有。

V3 §2.2 用 `astats` 量，絕對值比這次低約 3 dB，各段之間的落差一致。本規格的目標只看落差。

### 2.3 跟市面抽卡遊戲比

拿幾類常見做法比：原神、崩壞：星穹鐵道用流星或光的顏色預告稀有度；爐石戰記開卡包時，卡片翻開前先發出稀有度的光，傳說卡翻開有專屬音效；FGO 召喚有金色、彩色的光環；寶可夢 TCG Pocket 的閃卡反光跟著手機傾斜；戀與深空這類乙女遊戲抽到高稀有度時，角色本人有一段登場演出。差距集中在五件事：

1. **升階要停一下、要有聲音**：每升一階都有獨立的一拍和音效。我們藍和金只隔 0.25 s，也沒有聲音。
2. **高潮要疊層**：背景換色、放射光、衝擊波、遠近粒子、全螢幕泛光、鏡頭推近，通常好幾層一起。我們只有光刃、十字光、星塵。
3. **稀有卡要明顯不同**：普通卡快、樸素；稀有卡更長、更亮、更響。我們三種同一條時間軸、同一條配樂。
4. **角色本人要登場**：一句話、一段語音或會動的立繪。我們只有靜態照片。
5. **收藏要有回饋**：NEW、收集進度、重複角色的處理。我們只有落位發光。

我們比市面好、要保留的：**稀有度誠實**（不做「先假裝普通再變稀有」的升格演出）、按下到停住最快 3.2 s、整套對拍震動、reduce-motion 與 VoiceOver 版本、光球飛進真的那一格。

## 4. 時間軸（以 R0＝揭曉起點為 0，單位 ms）

### 5.15 等待心跳（Eric 2026-10-18 補充，同日「照預設」定案）

按下翻牌到 server 回來，平常有 1–2 秒空窗：卡背入場 0.5 s 走完後只剩慢慢呼吸，等待字樣要到 0.9 s 才淡入。這段加一個很輕的「咚咚」心跳，讓等待不空。以按下翻牌為 T＝0：

- **節奏**：卡背入場走完（T＋500）起，每 900 ms 一組「咚咚」，兩下相隔 140 ms；server 一回來立刻停，交棒給揭曉蓄力的三下 tick（每 200 ms 一下）。心跳 900 ms、蓄力 200 ms，聽起來是越來越快。
- **觸覺**：每下 `tick()`（selectionClick，最輕的一種）。第一組在按下那一下 `light()` 之後半秒；最多 6 組（到 T＋5000 左右）。server 超過 5 秒還沒回來就只剩畫面的呼吸，不一直震。
- **畫面**（跟觸覺同一拍）：卡背放大 1.2%（60 ms 衝上、90 ms 回落），第二下 0.8%；同時水平顫動 ±0.8 px（25 Hz、120 ms、遞減），徽記銀光 +0.12。疊在 §5.9 的等待呼吸上，不取代它。
- **做法**：心跳時點從 `_waiting` 推導，不另開 Timer（V3 鐵則）：`_kWaitingCycle` 2.6 → 2.7 s，一圈正好三組；跨過門檻才觸發（同 `_RevealBeat` 的做法），用組數計數停在第 6 組。
- **觸覺密度**：心跳發生在揭曉開始前，不算進 V3 D8 的揭曉 13 下。平常 server 1–2 秒回來，只會有 1–2 組（2–4 下 tick）。另設一個常數開關（同 `_kChargeTicksEnabled`），真機覺得太多可以關掉或只留畫面。server 回來時離上一下心跳不到 70 ms，蓄力第一下會被 `tick()` 自帶的節流略過，不補。
- **reduce-motion**：等待本來就靜止（`_waiting` 不跑），心跳的畫面和觸覺都不做。觸覺跟畫面是一組，畫面不動時只剩手機在震，容易被當成錯誤提示。App 的震動設定關掉時照舊不震（`AppHaptics.enabled`）。
- **聲音**：不加（等待期只有一次性咻聲，`docs/bug-log.md` 2026-07-16）。
- **真機再調**：週期 900 ms、兩下間隔 140 ms、放大 1.2%／0.8%、顫動 ±0.8 px、最多 6 組。

### 12.2 新測試要釘住的行為

1. **時間軸**：`standard` 與 `sr`（3.85 s）各自的節點嚴格依序、都在 `revealMs` 之內；`standard` 的值等於 V3。
2. **只翻一次**：兩條時間軸都每 50 ms 取樣，正面出現後卡背不再出現（K4 維持時）。
3. **稀有度誠實**：N 全程銀、線路遮罩不亮；R 不出現金；SR 先藍後金（兩條時間軸都驗）；徽記白光三種都一樣。
4. **閃光安全**：每一刀都用 60 fps 錄 N／R／SR，`tools/practice-reveal-flash-check` 量實際畫面（§3）：25 cm 任一秒 ≤ 2 次、20 cm ≤ 3 次，揭曉與收卡都算。單元測試守住量測靠的曲線條件：翻牌前卡背的白光只有徽記白光一下；卡片側立前 50 ms 之前，卡面前面不疊任何光；前層泛光、光刃、十字光各自只亮一次。翻牌閃光峰值 SR ≤ 0.25、R ≤ 0.12、N 恆 0；金色段的直光只長大一次、不重複閃。
5. **停住靜止**：鏡頭 scale 在停住前回到 1.0、微震歸零；所有粒子、光環、打字效果在停住前結束；`pumpAndSettle` 收得了。
6. **牌**：烙印前不存在、第一幀就是正確稀有度、回彈不小於 0.95、最後 1.0；最後位置超出卡片不超過 12 px、不出螢幕。
7. **NEW**：只有新卡有；重複角色有「已收藏」、沒有 NEW；抽牌中離開又回來（沒有紀錄）不掛 NEW。
8. **收集數字**：儀式期間顯示抽之前的數字，光球落位時才 +1 並跳一下；重複角色不跳；reduce-motion 直接更新不跳。

10. **聲音**：抽到哪個稀有度就播那一條；按下時三條都預載；收卡音不變；全程不呼叫 `playWaitingLoop()`；產生器的量測（全頻與手機近似）達到 §3。
11. **收卡**：細線階段 yaw 單調、光球落位仍在 450 ms；沒有目標格時原地收束。
12. **純函式**：衝擊波半徑單調、光尾寬度從頭到尾遞減、粒子同一時間點算兩次結果相同、每幀粒子合計不超過檔位上限。
