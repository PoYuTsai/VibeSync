## 1. 唯一主推薦

M8 不建立一張新的「VibeSync 全能 dashboard」。現行 App 沒有這張畫面，硬畫會把真實產品拍成概念產品。

唯一主路徑是現行 App 已存在的跨頁接力：

> **對象詳情頁**  
> → **該對象的真實作戰板**  
> → **鎖定該對象的問教練 Sydney 視窗**  
> → **同一個外部聊天 App**  
> → **兩則訊息依序送出**  
> → **短黑場**  
> → **同一個已送出狀態＋VibeSync 定位與 CTA**

這條路徑能用真實產品證明四件事：

1. VibeSync 認得的是「小安」這一位對象，不是匿名句子。
2. 它保留最近互動、分析次數與前後脈絡。
3. 它把本次投入度、目前階段與下一步分開表達，不把分數當成功率。
4. Sydney 提供方向，但最後兩則外部訊息由男主自行輸入與送出。

### 桌面主構圖

桌面不是把 App 改成桌面 dashboard。畫面中央保留一個約手機寬度的真實 App 產品平面，最多只露極薄裝置邊緣；M7 物件逐項對齊這個平面的真實垂直頁面。進入 Coach 後，產品面板移到左側，右側才重新取得外部聊天焦點。

### 手機主構圖

手機直接 edge-to-edge 顯示真實 App。產品頁、作戰板、Coach 與外部聊天依序接手全螢幕，不做桌面左右分割的縮小版，也不把手機再放進一支手機框。

## 4. M8 狀態模型

| 狀態 | 畫面 | 可逆性 | 可由「直接看產品」進入？ |
|---|---|---|---|
| `P1` | 對象詳情頁頂部：姓名＋最近互動 | 可回看 | 是 |
| `P2` | 本次投入度＋可信邊界 | 可回看 | 是 |
| `P3` | `準備邀約`＋下一步入口 | 可回看 | 是 |
| `P4` | 真實作戰板：已分析次數／互動脈絡／本輪訊號／下一步 | 可回看 | 是，唯讀入口停在此平台也成立 |
| `C1` | 鎖定 `小安` 的 Sydney 最終訊息 | 可回看，未發送時可退場 | 否 |
| `S1` | 男主第一則訊息已送出 | 事件不可逆；回捲只回看 | 否 |
| `S2` | 男主第二則邀約已送出 | 事件不可逆；本次瀏覽永久保留 | 否 |
| `B1` | 短黑場 | 只隔開人物選擇與品牌 | 否 |
| `F1` | 同一已送出狀態＋定位＋CTA | CTA 可互動；訊息狀態不倒退 | 否 |

### 4.1 兩次送出的離散規則

- 第一則與第二則各自只發生一次。
- 第一則已送出後，即使觀眾回捲到 Coach 再往前，第一則直接以已送出狀態回場，不重打、不收回。
- 第二則已送出後，任何回捲、resize、切換前景再回來，都不能把它退回輸入框。
- 訪客不替男主點送出。主敘事到達門檻時，由角色動畫完成；reduced-motion 的「繼續」只控制影片節奏，不是送出按鈕。
- 女生始終沒有已讀、輸入中、上線、回覆或社群動態。

### 4.2 「直接看產品」唯讀分支

- 點擊時記住當下電影進度與既有 sent flags。
- 進入獨立的 M8 產品預覽進度，只能觀看 `P1 → P4`。
- 預覽內的 App 頁面、作戰板 `問教練` 與下一步元件全部只讀；不觸發 `C1`、`S1`、`S2`。
- 固定提供 `返回電影`；返回後恢復原電影進度、鏡頭位置與既有 sent flags。
- 若點擊前尚未送出，預覽不能建立任何 sent flag；若點擊前已送出，預覽也不得清除。
- `在 App Store 下載` 可作為預覽的次要出口，但不顯示人物高潮，也不把預覽誤當片尾。

## 5. 桌面版 Storyboard

桌面基準構圖：16:9。真實 App 平面保持約手機寬度，不重排成 desktop dashboard。每次只讓一個產品區塊成為第一閱讀層。

### D1｜同一位對象：M7 平面停止透視

- **畫面／構圖**：M7 的姓名文字錨停止透視，對齊 `PartnerDetailScreen` AppBar 的 `小安`；同一字串再落到命令摘要大字。產品平面略偏右，左側留暗紫負空間。
- **第一閱讀層**：`小安`。
- **必要可讀文字**：`小安`、`最近一次：有在回應`、`最近互動`。
- **可略讀 microcopy**：具體日期、`接法`、個性／偏好 tags。
- **Sydney 位置**：不出現。
- **行動橘首次進場點**：電影層仍未進場。真實 App 既有的小型橘色 icon／badge 可留原尺寸，但降低曝光權重，不擴張、不發光。
- **正向狀態**：姓名、最近一次狀態、最近互動依序收正；攝影機停住讓三者被讀到。
- **反向狀態**：送出前可重新展開為 M7；任何 sent flag 已建立時只保留旗標，畫面仍可回看。
- **Reduced motion**：用 angled plane 靜態切換至正視產品頁；不做長距離透視收束。
- **對應 M7 起始物件**：同一位對象姓名錨＋時間路徑。
- **真實 App 來源**：`PartnerDetailScreen` AppBar、`_PartnerCommandSummaryCard`。
- **刪除而不虛構**：不畫對方頭像、不畫戀愛狀態、不用身份星座或成功率補空位。

### D2｜本次訊號不是關係結論

- **畫面／構圖**：同一真實 App 平面自然向下移到 `PartnerHeatHeroCard`；卡片接近正面，其他頁面內容退到上下裁切外。
- **第一閱讀層**：`對方這次的投入度`。
- **必要可讀文字**：`54`、`有在回應`、`只反映這次互動中的文字訊號，不代表關係進度。`
- **可略讀 microcopy**：`這次有回應，投入訊號普通`。
- **Sydney 位置**：不出現。
- **行動橘首次進場點**：仍無電影層行動橘；產品卡依真實 UI 呈現，不能把數字改成橘色成功儀表。
- **正向狀態**：分數與說明同時清楚；不能先讓大數字單獨停留很久，再晚到免責句。
- **反向狀態**：回到 D1，不倒跑分數動畫；回看使用固定終值。
- **Reduced motion**：直接顯示固定終值，不做 count-up。
- **對應 M7 起始物件**：投入度節點。
- **真實 App 來源**：`PartnerHeatHeroCard`。
- **刪除而不虛構**：不加愛心、不加「她對你有 60% 好感」、不把 orb 當資料球放大。

### D3｜目前階段與現在可做的事

- **畫面／構圖**：產品平面再往下到 `PartnerMindMapEntryCard`，下方只露出 `下一步行動` 卡的標頭與第一行，形成可進入作戰板的方向。
- **第一閱讀層**：`準備邀約`。
- **必要可讀文字**：`對象作戰板`、`準備邀約`、`下一步行動`。
- **可略讀 microcopy**：`可接話題` preview、下一步正文第一行。
- **Sydney 位置**：不出現；`問教練 Sydney` CTA 尚在頁面更下方，不提前抬入。
- **行動橘首次進場點**：產品原生 icon／下一步標籤維持小型橘色，不能成為情緒高潮。
- **正向狀態**：真實階段 pill 固定後，卡片邊緣成為下一幕作戰板的遮擋物。
- **反向狀態**：卡片退回原頁位置，不讓 `準備邀約` 倒成前一階段。
- **Reduced motion**：從入口卡 cross-dissolve 到真實作戰板標頭；階段文字位置維持一致。

- **刪除而不虛構**：本格不使用 `partner_stage_close.webp`；它不在這張真實卡內。

### D4｜產品 payoff：不是這一句，是同一個人的整段脈絡

- **畫面／構圖**：入口卡展成真實 `PartnerMindMapScreen`。上方標頭 `小安 的作戰板`，中間保留現行左到右樹狀圖，底部是真實 `_MindMapDetailPanel`。攝影機近乎正投影，不另排卡片。
- **第一閱讀層**：`小安・已分析 3 次`。
- **必要可讀文字**：`小安 的作戰板`、`小安・已分析 3 次`、`互動脈絡`、`目前互動重點`、`準備邀約`、`本輪訊號`、`下一步行動`。
- **可略讀 microcopy**：`上輪／上上輪`的實際摘錄、可接話題、完整歷程。只讓標籤與存在性可讀，不新增舊劇情。
- **Sydney 位置**：只在底部 `問教練` CTA 的功能位置出現，不顯示大立繪。
- **行動橘首次進場點**：下一步節點使用真實 App 小面積橘色；電影層仍不接管整體色彩。
- **正向狀態**：根節點先落定，再讓歷史、階段、本輪訊號與下一步依序取得焦點；最後停在可讀的全頁產品平台。
- **反向狀態**：焦點順序可逆，但分析次數與週三→週五→週六事實不逆轉。
- **Reduced motion**：以四個靜態 focus state 依序切換，樹本身不 pan／zoom；底部 panel 保持固定。
- **對應 M7 起始物件**：時間路徑、前後互動平面、銀灰可能線、階段、路徑終點。
- **真實 App 來源**：`PartnerMindMapScreen`、`PartnerMindMapView`、`buildPartnerMindMap()`。
- **刪除而不虛構**：不增加 HUD、不增加關係成功率、不把舊聊天全文填進節點、不另畫中央 DNA 球。

### D5｜Sydney 認得這一位，但不替他寫

- **畫面／構圖**：作戰板底部 `問教練` 的位置取得 Coach 紫邊，沿真實 route 解析成鎖定 partner scope 的 `GlobalCoachScreen`。標題清楚顯示 `問教練 Sydney・小安`；Sydney 44 px 圓形頭像與一顆真實泡泡幾何出現。
- **第一閱讀層**：`問教練 Sydney・小安`。
- **必要可讀文字**：`那個週五已經過了。你不用再猜她當時到底是什麼意思。現在，把你的意思說清楚就好。`
- **可略讀 microcopy**：Coach 記憶來源 strip、額度說明；情境 chips 留在裁切外或低於第一屏。
- **Sydney 位置**：真實 `CoachHeadAvatar(size: 44)`，只作訊息來源；不對嘴、不換 pose。
- **行動橘首次進場點**：仍未由電影層進場；Sydney 泡泡保持 Coach 紫／中性色。產品原生輸入框橘色 focus 不啟動。

## 10. 狀態、容錯與無障礙

### 10.1 資料狀態

M8 使用經審核的固定合成 fixture，不接 live account、Hive、Supabase 或即時 AI。因此主電影不存在 loading、network error 或空資料分支。

若 fixture 缺少以下任一資料，該版 animatic 直接判定不通過，不得用假 placeholder 卡補上：

- 對象姓名
- 本次投入度與 scope disclaimer
- `準備邀約`
- 已分析次數／互動脈絡
- 本輪訊號
- 下一步行動
- 鎖定對象的 Coach 標題

### 10.2 Reduced motion

- 每一格保留同樣的必要文字、來源頁與狀態次序。
- 透視、pan、長距離 camera 改為正視裁切與短 cross-dissolve。
- 不移除 D6～D8／M8-M6～M8-M8 的兩次送出；只移除逐字輸入動畫。
- `繼續` 控制放在聊天外、語意是播放下一段，不是「替男主送出」。

### 10.3 鍵盤與螢幕閱讀器

- `直接看產品`、`返回電影`、`在 App Store 下載` 都必須有可見 focus ring。
- 桌面可用 Space／Page Down／方向鍵推進閱讀平台；Esc 離開產品預覽並回到原電影位置。
- 產品預覽應以一段摘要先宣布：`VibeSync 產品預覽：小安的對象頁、投入度、作戰板與下一步。`
- 兩則外部訊息只在各自 sent event 後進入 live region；回捲不重複朗讀為新訊息。
- 最終互動焦點順序為：主 CTA → Privacy／Terms → 返回電影；定位文案本身不進入 Tab 順序，但仍先由閱讀順序宣告。

### 10.4 低效能／無 WebGL

- P1～P4 使用正視、可讀的真實 UI 圖層，不能只剩產品名稱。
- C1、S1、S2、F1 都由 DOM／可讀 UI 層承擔，不依賴 WebGL。
- 若產品背景材質失敗，仍保留 App 深色背景、文字、狀態與 CTA；不顯示破圖 icon。

## 11. 驗收問題

### 11.1 不靠旁白的五秒測試

完整 M8 看完後，10 位測試者至少 7 位能主動說出下列四項中的兩項：

- 這是同一個叫小安的對象。
- VibeSync 記得不只一段互動。
- 產品區分本次投入度與關係進度。
- 產品知道目前是準備邀約，並給出下一步方向。

### 11.2 產品責任邊界

至少 8／10 人能回答：

- Sydney 沒有替男主把訊息傳出去。
- 第二則邀約是男主自己的意思。
- 女生是否接受，影片沒有答案。

若 3 人以上誤以為 VibeSync 自動代發，D5→D6／M8-M5→M8-M6 分界失敗。

### 11.3 真實產品來源稽核

逐格檢查：

- 每個必要 UI 是否能指向本檔第 2 節的現行來源。
- 合成資料是否都標為 fixture，而不是宣稱來自真實使用者。
- 是否把 report dock 的 stage raster 錯放進作戰板。
- 是否出現現行產品沒有的對方頭像或成功率。
- 是否讓 microcopy 搶過第一閱讀層。
- 桌面是否偷偷重排成 dashboard；手機是否只是桌面縮小。

### 11.4 反向與唯讀分支

- 從每一個 P1～P4 位置點 `直接看產品`，返回後進度誤差必須不可感知。
- 直接看產品永遠不出現 Sydney 最終訊息或任何 sent event。
- S1 後回捲再前進，第一則不重打。
- S2 後回捲、resize、背景切換再回來，兩則均仍已送出。
