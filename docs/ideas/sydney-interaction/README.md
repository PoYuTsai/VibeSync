# Sydney 互動與「動起來」設計（參考競品影片）

> 發想文件，接續 PR #72（Sydney 教練頁動態背景與長文 UX）。依 PR #72 的約定，UI／品味與實作方式仍由 Bruce 裁決；本文提供一套可直接開工的互動模型、素材規格，以及配套的 nano banana 提示詞包（見 `nano-banana-prompts.md`）。只新增文件，不改 App，不動額度、付費與 AI 請求。

## 1. 影片看到什麼、借什麼

Eric 提供的 7 秒錄影是競品聊天頁（真人感角色「薔薔」全螢幕當背景，泡泡疊在身上）。逐格觀察後的取捨：

| 影片做法 | 借不借 | 對 VibeSync 的意義 |
| --- | --- | --- |
| 角色全螢幕當「活的背景」，鏡頭固定，角色循環做小動作（整理衣襬、換重心、看鏡頭） | 借在場感與固定機位 | Sydney 成為教練頁背景；動作幅度要更小、更像「在聽」，不是走秀 |
| 泡泡半透明疊在角色身上；臉留在畫面上四分之一，泡泡儘量不壓臉 | 借 | 現有 glass 泡泡直接可用；版面規則：臉區不放泡泡 |
| 動作是純環境循環，和你打字、她回覆完全無關 | 不借 | 差異化：Sydney 隨對話狀態換姿態（聽、想、講、收尾），這才是「互動」 |
| 鍵盤升起時角色不縮、不重排，只是下半身被蓋住 | 借 | 鍵盤時 Sydney 位置不動，臉仍可見 |
| 等待時出現「回覆中…」小泡泡 | 借 | 對應現有 `CoachChatProgressNotice`，加上思考姿態 |
| 右上「換形象」（換造型、場景） | 先預留 | 之後可做訂閱權益「Sydney 造型」；提示詞包附一組，不是本次決定 |

## 2. 互動模型：五個狀態、三個彩蛋、一個退讓機制

### 2.1 狀態（全部由現有訊號驅動）

| 狀態 | 觸發訊號 | Sydney 的動作 | 用到的幀 |
| --- | --- | --- | --- |
| 待機 | 無事件 | 呼吸由程式做（scale 1.000→1.012，4 秒正弦）；隨機每 3–6 秒眨眼一次（S01→S02→S03→S02→S01，每格約 60–80ms）；偶爾瞄一眼輸入列 | S01、S02、S03、S04 |
| 聆聽 | 輸入框 focus，或輸入框有字 | 頭微側、視線落到輸入列、閉嘴微笑；上身前傾用 `Transform` 補，不靠圖片 | S10、S11 |
| 思考 | 送出後 `isLoading` 為真，尚未收到第一段回覆 | 送出瞬間先點頭一拍（S12），再進托下巴思考；等超過幾秒偶爾切到「想到了」幀 | S12、S20、S21 |
| 講解 | 第一段回覆到達、串流中 | 先一拍「提示」手勢（S30），接著進入陪讀：視線往下跟著文字，每個段落點一次頭 | S30、S31、S32、S12 |
| 收尾 | 回覆完成；或錯誤、逾時 | 完成：回待機並淡淡一笑。錯誤：歪頭抱歉一拍再回待機 | S01、S40 |

換幀一律 crossfade（`AppMotion.state` 240ms、`AppMotion.easeOut`），不做瞬跳；姿態之間的位移用 `Transform`（translate、scale）補，不要靠圖片本身位移，幀才疊得起來。

### 2.2 彩蛋（互動回饋，稀有才珍貴）

- 點一下 Sydney：從 {揮手 S50、推眼鏡 S51、眨眼比讚 S52} 隨機一個，播一拍後回到目前狀態；8 秒冷卻，連點不重播。
- 使用者訊息含成功訊號（例：約到了、她回我了），或教練回覆是鼓勵段：S52 一拍，套 20% 機率閘（同 `plans/004-coach-pose-frequency.md` 的降頻精神）。
- 開場泡泡的 44pt 頭像（`CoachHeadAvatar`）也會眨眼與點頭：所有幀共用同一機位，同一個裁切框直接套用，不需要另一套素材。

### 2.3 退讓機制（回應 PR #72 的核心問題：長文來了，空間給誰）

三段「在場檔位」，由內容高度與鍵盤決定：

| 檔位 | 條件 | 版面 |
| --- | --- | --- |
| A 全身在場 | 開場、短問答 | Sydney 佔上方約 55%（同 PR #72 預覽），對話在下 |
| B 陪讀 | 回覆超過約 6 行，或對話內容高度超過可視區 40% | Sydney 在 240ms 內上滑並縮成上緣約 22% 高的頭肩（用陪讀幀 S32），閱讀區拿走其餘空間。捲到底不再放大，避免版面跳動；點她或新一輪送出才回 A |
| C 角落 | 鍵盤升起且已在 B | 縮成 44pt 頭像貼在標題列或輸入列旁，仍會眨眼、點頭 |

減少動態（`motionDisabled`）時：停呼吸與眨眼，只保留狀態換幀的 crossfade；離開頁面靠 `TickerMode` 停 ticker；App 進背景時停計時器。

## 3. 技術路線：兩層，先做便宜的那層

| 層 | 做法 | 需要的素材 | 備註 |
| --- | --- | --- | --- |
| 第一層（先做） | 純 Flutter、不加套件：同機位幀 crossfade（沿用 `HomeCoachPresence` 的 `AnimatedSwitcher` 寫法）＋ `Transform` 做呼吸與前傾 ＋ `Timer` 做眨眼 | 約 16 張同機位透明 WebP | 光這層就有「活著」的感覺；nano banana 提示詞包就是為這層設計 |
| 第二層（之後） | 把起訖幀餵 image-to-video（Veo、Kling 類）產 2–4 秒循環 → 綠幕去背 → 動態 WebP（`Image.asset` 原生會播），或交 Rive 綁骨架做 state machine | 第一層的幀當起訖幀 | 先看角色一致性、循環接點、髮絲邊緣，再看檔案大小與實機流暢度 |

## 4. 素材規格（讓幀能疊在一起）

- 畫布：直式 2:3（與現有 1023×1537 同系統）。主幀 S01 是基準，其餘幀全部從 S01 用編輯模式改出來。
- 構圖：腰上中景，頭水平置中，眼睛約在畫布頂端往下 22% 處；身體在下緣被切掉，下緣淡化由程式的 ShaderMask 負責。
- 背景：純綠 #00FF00、無陰影，去背後存透明 PNG，再轉 WebP（約 100–200KB／幀，16 張約 2–3MB，進 `/coach` 時 precache）。
- 對齊：以 S01 眼睛中心為基準平移對齊；眨眼與嘴型若身體漂移，改成「S01 身體＋只貼眼睛小塊」的合成法，穩定度最高。
- 量測：每張幀量 bbox 與人物中心，記進 enum（`HomeCoachPose` 的做法）。
- 檔名：`sydney_s01_idle_open.webp`、`sydney_s03_idle_blink.webp`……與提示詞包編號一致。
