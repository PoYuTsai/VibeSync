# 開場救星：開場白的底氣（研究備忘）

- 日期：2026-09-27
- 分支：`claude/opener-confidence-tone-6f9p6z`（只有文件：沒改程式、沒呼叫付費模型）
- 依據：repo HEAD `42eb022` 的程式碼與 `tools/opener-plan-write-eval` 語料

新版開場救星會寫出「問妳一個沒營養的問題」「問個無聊問題」「隨口說說」這類替自己打折的句子。這份備忘整理它們從哪裡來、為什麼會發生、自信的邊界在哪裡，以及建議怎麼改。

## 1. 結論

這三句是寫手 prompt 的設計造成的，不是模型偶爾抽風。寫手 prompt 每一條規則都在降低她回覆的負擔，沒有一條規定用戶該用什麼姿態說話。模型要把一句話變得低壓、好回，最省事的做法就是在句子裡直接宣告這題不重要。挑卡和評測也都不檢查這件事，所以其中一句還被選成了 AI 推薦。

要的語氣：**理所當然的自信、不猶豫、說的話有份量**。要拿掉的是「對自己發言價值的撤回」；要保留的是對事實的誠實與正常的禮貌。自信不是強硬。

修改要落在新版路徑（`opener_write.ts`、`opener_pick.ts`、`opener_plan_write.ts`）與評測（`judge.ts`）；只在舊 `opener_prompt.ts` 加「自信一點」改不到截圖對應的那條路。

## 2. 截圖裡的三句

截圖上的卡片名稱只有新流程「規劃 → 寫手 → 挑卡」會用到。這條路要旗標 `OPENER_PLAN_WRITE=true`，而且新版 App 送出 `openerCardSet=2`（`opener_flow_handler.ts:667`）。卡片名稱對應寫手的五個欄位：直接接話＝extend、換個角度＝resonate、換個方向＝tease、輕鬆一點＝humor、帶到自己＝coldRead（`opening_rescue_screen.dart:163`）。

三句分成兩類：

| 類別 | 卡片 | 原句 | 打折方式 |
|---|---|---|---|
| A 貶低自己的問題 | 輕鬆一點（humor） | ~~問妳一個沒營養的問題，~~妳今天午餐吃什麼 | 先請示，再說自己的問題沒營養 |
| A 貶低自己的問題 | 輕鬆一點（humor） | ~~問個無聊問題，~~妳是那種會重複刷同一部劇的人嗎 | 說自己的問題無聊 |
| B 撤回份量、叫她隨便回 | 直接接話（extend）**AI 推薦** | 最近有沒有迷上什麼新東西~~，隨口說說~~ | 句尾多一句要她隨意回答；沒有直接說「我的話不算數」，但把邀請聊天的態度弄鬆了 |

- 前兩句的來源指令：「同一件事，語氣輕鬆一點的問法」（`opener_write.ts:48`）。
- 第三句的推薦理由寫著「問題夠開放又不預設立場，她可以隨便挑一件事聊」，幾乎是把沒線索時的那行指令原封講回來：「開一個不預設她任何事實、她好回答的低壓話題」（`opener_write.ts:101`）。
- 三句都沒接到她的任何資料。截圖把對方資料解讀收起來了，所以「這幾局沒有可接線索」是推測。截圖下方寫著已儲存成草稿，所以也不能只靠畫面證明當下的伺服器旗標與模型版本。
- 問題不只在幽默卡：五張卡、推薦句、改寫後的句子、範例訊息都要守同一個標準。

### 2.1 改寫示意（人工示範，不放進 prompt）

| 原句 | 最小修改（伺服器拿掉打折句後會長這樣） | 更好的寫法（prompt 該寫出來的） |
|---|---|---|
| 問妳一個沒營養的問題，妳今天午餐吃什麼 | 妳今天午餐吃什麼 | 今天午餐吃了什麼好料 |
| 問個無聊問題，妳是那種會重複刷同一部劇的人嗎 | 妳是那種會重複刷同一部劇的人嗎 | 重刷最多次的是哪部劇 |
| 最近有沒有迷上什麼新東西，隨口說說 | 最近有沒有迷上什麼新東西 | 最近迷上什麼新東西 |

- 右欄有些句子換了提問角度（「吃什麼」和「吃了什麼好料」不完全同義），不能當機械替換；用戶明確指定要問的事時，優先保留他的問題。
- 拿掉打折的話只是第一步。「午餐吃什麼」自然但普通；她的資料有線索時，應該從線索問一個真的有內容的問題，不要為了補趣味再加一句包裝話。
- 拿掉打折的話之後直接問就好，不必反過來加命令或條件（像「不准回隨便」）。那對陌生人太強硬，是另一種用力。自信是理所當然地問，禮貌是不逼她。

## 3. 為什麼會這樣

### 已從程式碼確認

1. **寫手 prompt 從第一版就沒有姿態規則。** `opener_write.ts:22-33` 全部在講她：好回、不用接受考核、不用配合演出、「問號多像在索取資訊」。9/25 第一版（`04847f9`）就是這樣。舊版 prompt 原本有「框架維持：評價權留在自己手上」「非乞求感」「長度本身就是位階訊號」（`opener_prompt.ts:152`、`:270`、`:285`），重寫時沒帶過來。新版寫手是獨立 prompt，舊檔裡有「自信」二字不代表新版模型有收到。
2. **「輕鬆一點」的定義本身就在要求打折。** `opener_write.ts:48` 規定問題本身不變、只換語氣，模型能動的只剩句首和句尾。中文聊天裡「輕鬆」最現成的講法，正好是「問個無聊問題」。三句裡有兩句出自這張卡。
3. **沒線索時的指令只有降壓詞，沒有做法。** `opener_write.ts:101` 寫「不預設她任何事實、她好回答的低壓話題」。沒有具體素材能讓題目本身變好回，模型就改用嘴巴宣告「隨口說說」。
4. **挑卡沒有防線。** `opener_pick.ts:115-138` 檢查紅線、兩個問號、長度、照抄自介、自述位置、外文字。三句各 22、17、19 字，沒有兩個問號，沒有第一人稱經歷開頭，一分都不會扣；所以「隨口說說」那句能被選成 AI 推薦。而且改寫只由紅線觸發，若只加一個降級分數，打折句仍會留在備選卡裡。
5. **評測看不到這個問題。** `tools/opener-plan-write-eval/cases.json` 的 22 題每題都有 1–3 條線索，沒有一題走沒線索那條路。評審代碼（`judge.ts:15-45`）沒有「替訊息打折」這一項，`awkward` 抓不到語法自然、容易回答的「問個無聊問題」。Bruce 的校準與盲測語料共 204 句，一句打折句都沒有。

專案其實已經有這個概念：analyze-chat 的語意評審 `beta_pattern` 裡就寫著「為表達興趣道歉」（`_shared/social/semantic_critic.ts:244`），只是開場救星沒用到。

### 推論（還沒用付費測試驗證）

- 「問號多像在索取資訊」可能讓模型覺得開口問就是在跟她拿東西，於是先道歉。次要誘因。
- 「謙虛帶一句」（`opener_write.ts:31`、`:49`；`judge.ts:33`「謙虛一句」）原意是防炫耀、防拿共同點當資格，但「謙虛」沒有界定程度，可能把整體語氣往軟的方向推。這三句都沒有自述，所以它不是這三句的直接成因；Bruce 給的標準範例「我最近都跑環河公園那…妳都跑哪？」也不特別謙虛，只是自然。

## 4. 自信的邊界

| 要的 | 在句子裡的樣子 | 不要誤解成 |
|---|---|---|
| 理所當然的自信 | 第一個字就是內容，預設自己的好奇值得交流 | 宣布「我很有價值」、刻意展示優越 |
| 不猶豫 | 不疊「可能有點、隨便問問、不重要啦」 | 對不知道的事強行斷言 |
| 說的話有份量 | 有明確想知道、想分享或想回應的內容 | 要求她認真回答、下命令、替她斷言意願 |
| 輕鬆 | 口語、簡潔、趣味從話題本身長出來 | 先說自己的問題很廢 |
| 有禮貌 | 直接問，語氣像對朋友 | 每句改成命令或硬式陳述 |

保留的東西：「我猜這是在台南拍的，對嗎」是對未知事實留餘地；「我好奇妳最喜歡哪道菜」是真好奇；「這間我還沒去過，妳最推哪一道」是誠實交代程度（前提是用戶真的說過沒去過）。這些都不是沒自信。

過度修正的反例（一樣不合格）：「妳一定很想回我這題」（替她斷言意願）、「認真回答我，妳午餐吃什麼」（把自信寫成命令）。

## 5. 建議怎麼改

### P0：寫手 prompt（`opener_write.ts`，只影響新版 App）

**① 在 `SENTENCE_RULES` 後面加一段姿態規則（兩種卡組共用）**

```
## 說話的姿態：理所當然
- 這則訊息本來就值得她回：第一個字就是內容，不先替它打折。
- 不評價自己的問題（無聊、沒營養、蠢、廢、亂問、隨便問問）；不請示、不預告（問妳一個問題、想請問、不好意思、打擾一下、冒昧）。
- 不替她降低回答的份量（隨口說說、隨便回、想到什麼說什麼、不用當真、不回也沒關係）。
- 好回答靠題目具體、她一句就能答，不是靠說這題不重要。低壓是她回得輕鬆，不是你講得心虛。
- 自信不是強硬：不命令、不催、不給她條件（不准回隨便、一定要回、快說），不宣稱自己的話很重要，不替她斷言她會想回；直接問，語氣還是像對朋友那樣客氣。真的好奇、正常禮貌、對不確定的事說「我猜」都可以留。
- 每則寫完，遮掉開頭那段鋪墊或句尾那段補充再讀：意思沒變，就刪掉。剩下的句子太空泛，就回到給你的線索把問題寫具體，不要再加一句包裝。
```

**② 輕鬆一點（第 48 行）**

```diff
- humor（輕鬆一點）：同一件事，語氣輕鬆一點的問法。
+ humor（輕鬆一點）：同一件事，用更口語、俐落或帶一點小趣味的方式開口；趣味在內容裡，直接進話題。不先說問題無聊、沒營養，不叫她隨便回，也不硬加笑點。
```

**③ 沒線索分支（第 101 行）**

```diff
- 她的線索都不適合：開一個不預設她任何事實、她好回答的低壓話題
+ 她的線索都不適合：開一個不預設她任何事實、她一句就能回答的具體小話題；直接問，不說這題無聊，也不叫她隨便回
```

**④ 「謙虛帶一句」改成「照原句程度自然帶一句」（第 31、49 行）**

只換用詞，位置規則（問完她之後）與來源限制（照原句、不當資格、不硬抓共同點）都不動：

```diff
- …或問完她之後謙虛帶一句時才用…
+ …或問完她之後照原句程度自然帶一句時才用（不誇大、不當資格，也不把自己講得很差）…
- coldRead（帶到自己）：有用戶自述時，先問她，問完再謙虛帶一句用戶自己的事。
+ coldRead（帶到自己）：有用戶自述時，先問她，問完再照原句程度自然帶一句用戶自己的事。
```

**⑤ 改寫器同一標準（`OPENER_REWRITE_PROMPT`，第 139 行）**

目前寫「保留原本要接的事與語氣」。加一句：「改寫時不加自我貶低或退縮的鋪墊，也不加命令或強勢話術。」避免改寫其他紅線時把打折句帶回來。

**⑥ 不動 `OPENER_FLOW_PROMPT_VERSION`**

它進了生成輸入指紋（`opener_stage.ts:569-590` 的 `computeOpenerGenerationInputHash`），改了會讓部署前後的同一請求算成不同輸入，影響重播與不重扣。寫手 prompt 改版只在 telemetry 加一個 `writerPromptRevision`（不進 hash、不含用戶原文），方便事後比對線上 log。

補一條測試確認新規則在 prompt 裡：那只是防文字回退，不證明行為改善；行為要靠下面的 A/B。刻意不放正面示範句，因為 repo 已經吃過示範句被逐字照抄的虧（`opener_prompt.ts:194`，還有「環河公園」）。

### P1：其他生成入口一致（`opener_flow_prompt.ts`、`opener_prompt.ts`）

- `opener_flow_prompt.ts`（旗標關、或舊版 App 的兩段式路徑）一樣沒有姿態規則。`:94` 寫「低壓話題」，`:112` 寫「誠實的低假設話題」，「誠實」很容易被讀成「承認這題很普通」。加同一段規則，這兩處照 ③ 的方式改。
- `opener_prompt.ts`（舊單段入口）本身就同時鼓勵「輕自嘲、降壓、隨口感」與「自信、非乞求感」；加一句區分「自嘲生活細節可以，貶低自己的發言不行」即可。
- `new_topic_prompt.ts` 已有「不自貶」（`:82`），例子針對等回覆、討安撫；截圖都在開場白分頁，沒有證據新話題有同樣問題。這次不動，列為之後的一致性檢查。

### P2（選配，需要 Eric 決定）：伺服器端直接拿掉打折句

仿照「emoji 直接拿掉」（`opener_pick.ts:66` 的 `withoutEmoji()`）：句首或句尾**整個子句**是打折句才拿掉（句首後面、句尾前面都要有標點），各最多剝兩層，拿完少於 6 字就保留原句。套用在 `opener_plan_write.ts:329`（寫手輸出）和 `:386`（改寫輸出），五張卡與範例卡都走同一套；理由欄若也出現同樣的打折詞就一併拿掉；telemetry 記每張卡有沒有被剝（不含原文）。

離線檢查（免費，沒有呼叫模型）：

| 檢查 | 結果 |
|---|---|
| 打折句正確拿掉（三句原句＋12 種變體：很廢、亂問的、不用當真、請教一下、隨便回就好…） | 15 / 15 |
| 正常用字不誤傷（哪部劇最無聊、無聊時做什麼、隨口哼歌、我好奇、我還沒試過、我猜…對嗎、問題來了…，含 Bruce 的兩句原句） | 13 / 13 |
| Bruce 校準與盲測語料被誤改 | 0 / 204 |

規則草稿（實作時再收斂）：

```js
// 句首：請示、替問題打折的整個子句（後面要有標點）
const HEDGE_LEAD_RE = /^(?:欸|那個|先|我)?(?:(?:問|請教)(?:妳|你)?(?:一)?(?:個|下)?(?:很|有點|超|比較)?(?:無聊|沒營養|蠢|白癡|廢|奇怪|私人|冒昧)?(?:的)?(?:問題|的)?|(?:隨便|隨口|亂)(?:問問|問一下|問)(?:的)?|冒昧(?:問一下|請問)?|不好意思|打擾(?:一下)?|想請問|不重要)(?:喔|啦|哈+)?[，,：:、\s]+/u;
// 句尾：撤回份量、叫她隨便回的整個子句（前面要有標點或問號）
const HEDGE_TAIL_RE = /[，,\s？?]+(?:就)?(?:我)?(?:只是)?(?:隨(?:口|便)(?:說說|講講|聊聊|回回|回|問問|問)|不用想太多|不用當真|想到什麼說什麼|不回也沒關係|亂問的|亂問|沒營養的問題|無聊問題|不重要)(?:啦|喔|哈+|就好|而已)?[。.]?$/u;
```

為什麼用「拿掉」而不是「紅線 → 再叫一次模型改寫 → 仍踩就丟卡」：

- 拿掉不花模型呼叫；改寫要用掉唯一一次額外呼叫，而那次常已被格式修復用掉。
- 拿掉的結果就是 2.1 的「最小修改」欄，句子仍完整、卡片不會少；改寫路線會提高少一張卡的機率。
- 兩條路能抓到的句型一樣（都要先有偵測器），改寫路線沒有多出涵蓋範圍。
- 限制：換句話說、打折詞在句中（「這題有點廢」）都抓不到，主力還是 prompt。若 A/B 顯示句中變體常出現，再考慮把「高精確度的句中命中」接到既有那一次改寫呼叫。
- 這跟 9/25「不靠詞表」的方向有點張力；不過那條講的是讀用戶補充，輸出端本來就有 emoji 與黑名單的前例。不做「出現某個字就刪」的黑名單。

### 評測

**評審代碼（`judge.ts`）加兩個，各附逐字證據：**

- `speech_self_discount`：句子以自己的問題、話題或發言為對象，明說它無聊、沒營養、不值得聽或不重要，並以此當開口鋪墊或撤回。形容劇情、描述無聊心情、引用對方的話都不算。
- `retreat_filler`：核心提問已完整，卻另外加上「我只是隨口說說／不用當真／隨便問問」等撤回，或叫她隨便回的句尾。刪掉不影響原意；正常事實、必要界線與合理禮貌不算。

`judge.ts:33` 的「謙虛一句」暫時不改：那份 prompt 是用 Bruce 9/23 作答校準過的，改字就要重跑校準（約 US$0.5）；要改就跟新代碼一起改、一起校準。

**真人盲評多加一題正向問題：**「這句是否讓人感覺：他知道自己想聊什麼，也自然認為這件事值得交流？」不要拿「沒有問號」「沒有『可能』」當自信的代理指標。

**回歸案例（免費、離線）：**

| 面向 | 要驗證的行為 |
|---|---|
| 三張截圖原句 | 被標記並修掉對應的打折句 |
| 語意近似 | 「問個很廢的問題」「我亂問的，不重要」「不用當真」不靠只列三句才抓到 |
| 正常用字 | 「無聊時做什麼」「我好奇」「我還沒試過」「我猜…對嗎」不被誤擋 |
| 過度修正 | 「妳一定很想回我這題」「認真回答我」不被當成合格的自信 |
| 五張卡一致 | 不只推薦卡；輕鬆卡、其他備選、範例卡都檢查 |
| 理由與引用 | 拿掉打折句後，理由不再說「用沒營養降低壓力」 |
| 沒線索的局 | `cases.json` 補：只有名字、只有一張自拍、自介只寫 hi、篩選型自介沒有正向線索 |
| 真實性 | 不為了自信加入虛構經歷、共同點或她的意願 |
| 新舊路徑 | 旗標開／關、cardSet 1／2 的語氣一致，schema 不變 |

**付費 A/B（要 Eric 說「跑」才執行）：** 8–12 組情境 × 每組 3 次 × 新舊 prompt 兩版；情境涵蓋資料很少、跳過補充、用戶要求輕鬆、有自述、沒經驗、追劇、飲食。真人先看匿名輸出判斷願不願意原封傳，再揭版本；評審模型只做初篩。依 README 單價推估約 US$1.5（生成約 72 次加評審）。輸入輸出留檔可重現；用合成情境，不用真實用戶資料。

**首輪驗收：**

| 指標 | 通過條件 |
|---|---|
| 打折句 | 回歸案例全部修正；新樣本的所有可交付卡都沒有（含人工找同義變體，不只查原字串） |
| 誤擋 | 正常用字案例全部通過 |
| 過度強勢 | 沒有新增命令、炫耀、考核或替她斷言意願 |
| 原意與來源 | 沒有因修語氣改掉用戶指定的問題、捏造自述或碰禁談詞 |
| 品質 | 盲評多數偏好候選版；分歧集中在某一卡型就先修那卡型 |
| 交付 | 成功率、少卡率不比現況差；記錄剝除率 |

小樣本零命中不代表不會再發生，這組案例留作之後每版的回歸。

### 實機驗收（Eric 的 iPhone）

- 不能只打開原來那份草稿看：App 會保存生成結果，伺服器也會重播同一個 generationId。改完 prompt 後舊草稿仍是原句，不代表修正失敗。分三件事看：舊草稿保留原句且不重扣；新生成用新語氣；同請求重試回既有結果、不重扣。
- 用追劇、午餐、資料很少的案例重新生成，五張卡是否都直接開口。
- 滑到「輕鬆一點」，確認輕鬆來自內容，不是「問個很廢的問題」。
- AI 推薦不再選帶退縮尾句的訊息。
- 正常的「我好奇」「我還沒試過」在有來源時仍能自然出現。
