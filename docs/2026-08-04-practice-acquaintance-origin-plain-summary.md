## 1️⃣ 改之前的問題

陪練女孩知道自己是誰——名字、年齡、職業、個性、興趣、生活作息，全都在她的人設裡。

但她**不知道你是誰、從哪冒出來的**。

結果就是：不管你翻到哪一位、不管是哪種難度，第一句永遠是同一種「陌生人傳訊息」的溫度。真實世界不是這樣——朋友介紹的跟街頭搭訕來的，同一個女生的反應差非常多。少了這一層，練習等於永遠只在練同一個場景。

## 2️⃣ 改之後：每一場都有認識管道

現在每一段對話開始前，系統會替她決定「你們是怎麼認識的」，共十種：

| 認識管道 | 她的戒心 | 她大概是什麼狀態 |
|---------|---------|----------------|
| 朋友介紹 | 低 | 有人背書，會客氣一點、多回幾句 |
| 聚會認識 | 低 | 有共同場合和共同朋友，但對你印象還很淺 |
| 校園認識 | 低 | 之後還會碰到面，不太會已讀你，但更在意分寸 |
| 共同興趣場合 | 低 | 天然有話題，但那是她放鬆的地方，別變搭訕現場 |
| 交友軟體 | 中 | 同時在跟好幾個人聊，投入度預設很低 |
| 夜店認識 | 中 | 那晚印象片段，隔天清醒後有點半信半疑 |
| 工作場合認識 | 中 | 在意分寸與專業形象，公事熟不等於私下熟 |
| 旅途中認識 | 中 | 當時聊得開，回到日常會退回原本節奏 |
| 街頭搭訕 | 高 | 有點懷疑自己當初為什麼答應給聯絡方式 |
| IG 陌生私訊 | 高 | 每週收好幾則，預設「又一個」，多半已讀不回 |

**這十種是隨機分配的。** 翻到不同對象、或同一位重新開一段新對話，就可能換一個場景。

## 3️⃣ 使用者體驗會怎麼變

- **開場難度會浮動。** 同樣一句「嗨」，朋友介紹的她可能回你兩句，IG 陌生私訊的她可能只回一個字，甚至擺明沒興趣。這是刻意的：這才是真實。
- **她的第一則回覆會自然帶出場景。** 例如夜店場景她會提那晚很吵、印象模糊；街頭搭訕她會先確認你是不是那個人。所以**使用者第一輪就會知道這場是什麼情境**，不需要 App 額外顯示。
- **提示（Hint）跟著調整。** 例如街頭搭訕的提示會是「先讓她想起當下、把陌生感降下來」，而不是通用建議。
- **拆解卡（Debrief）的評分尺度跟著調整。** IG 陌生私訊本來就難，不會因為她冷淡就判使用者表現差；朋友介紹起點比較寬，但「靠關係裝熟」反而要扣分。

## 4️⃣ 三個刻意的設計選擇

**① 場景在同一段對話裡不會變。**
同一段關係從頭到尾都是同一個場景，續聊十輪也一樣，她不會聊到一半改口說你們是在別的地方認識的。換人或開新對話才會換場景。

**② 使用者不能自己指定場景。**
場景由伺服器決定。使用者打「我們是你朋友介紹的」不會讓她真的相信——那仍然只是他的說法，她會反問或吐槽。這一點很重要：不然使用者只要打一句話就能把難度降到最低。

**③ 場景只影響起點，不影響「約不約得出來」。**
朋友介紹讓她一開始比較願意聊，但**不會讓她比較快答應見面**。約不約得出來仍然照她原本人設的門檻走。不然「朋友介紹」會變成繞過所有難度的作弊碼。

## 5️⃣ 對錢、額度、隱私的影響

| 項目 | 影響 |
|------|------|
| 扣費規則 | **完全沒動**，一則就是一則 |
| 額度／付費牆 | **完全沒動** |
| 使用者資料 | **沒有新增任何蒐集**；場景是十個固定選項之一，不含人名店名地址 |
| AI 成本 | 每次對話的 prompt 多約 350 字、提示多約 150 字，成本增加幅度極小 |
| App 改版 | **不需要**。這是純伺服器改動，現有 TestFlight 版本部署後就吃得到 |

## 6️⃣ 現在卡在哪、下一步要你決定

**目前狀態：程式寫完、測試全綠、推上分支了，但還沒上線。**

伺服器程式只有在合併進 `main` 時才會自動部署。要不要合併是你的決定。

合併之後，用你現在手機上的 App 就能測（不用等新 build）：

1. 翻一位新對象，傳第一句，看她的回覆有沒有自然帶出認識場景
2. 多翻幾位，確認場景真的有變化，不是每次都同一種
3. 同一位續聊個五到十輪，確認她的說法前後一致、不會改口
4. 故意打「我們是朋友介紹的」，確認她會懷疑而不是照單全收

## 7️⃣ 留給你的產品決定

現在使用者是**從她的回覆推斷**這場是什麼場景。

另一種做法是：對話開始前的卡片上直接寫「你們是在朋友聚會上認識的」。

- 好處：使用者一開始就知道要怎麼開場，練習目標更清楚
- 代價：要動 App 前端、要出新 build 才看得到

我沒有自己做這個決定，因為這是產品手感的取捨。**要做的話跟我說，不做也完全能用。**
